🔥 สรุปคู่มือการตั้งค่า Firebase Multi-Site Hosting

คู่มือฉบับสมบูรณ์สำหรับการจัดการหลายเว็บไซต์ใน Project เดียว ผ่าน Firebase CLI

Project หลัก: owlvy-carefulness-contest | ตำแหน่ง Local: G:\owlvy-carefulness-contest\

📌 ภาพรวมการเชื่อมโยงระบบ (3 โฟลเดอร์ย่อย)

ระบบจะเชื่อมโยง **โฟลเดอร์ในคอมพิวเตอร์** เข้ากับ **ชื่อเว็บไซต์บน Cloud** โดยใช้ **Target Alias** เป็นตัวกลาง

โฟลเดอร์ในเครื่อง (Local) Target Alias (ชื่อย่อ) Site ID บน Firebase Cloud App URL ใช้งานจริง
folder-contest target-contest owlvy-carefulness-contest owlvy-carefulness-contest.web.app
folder-exam-g6 target-g6 owlvytrio-g6-classroom-ai-exam-live owlvytrio-g6-...web.app
folder-admission target-g7 admission-to-g7-live-test admission-to-g7-...web.app

1 สร้าง Site บน Firebase Console (ฝั่ง Cloud)

  1. เข้าเว็บไซต์ Firebase Console เลือกโปรเจกต์ owlvy-carefulness-contest
  2. ไปที่เมนู Build > Hosting
  3. เลื่อนลงไปด้านล่างสุด ตรงหัวข้อ Advanced คลิกปุ่ม Add another site
  4. ตั้งชื่อ Site ID ใหม่ เช่น owlvytrio-g6-classroom-ai-exam-live และ admission-to-g7-live-test

2 จัดโครงสร้างโฟลเดอร์ในเครื่อง (Local Drive)

สร้างโฟลเดอร์ย่อยไว้ภายใต้โฟลเดอร์หลัก G:\owlvy-carefulness-contest\ ดังนี้:

📁 G:\owlvy-carefulness-contest\
 ├── 📄 .firebaserc           (ระบบสร้างให้อัตโนมัติจากการจับคู่ Target)
 ├── 📄 firebase.json         (ไฟล์ตั้งค่าหลัก ห้ามเขียนทับ!)
 │
 ├── 📁 folder-contest        (เก็บไฟล์เว็บเดิม)
 │    ├── 📄 index.html
 │    └── 📁 images
 │
 ├── 📁 folder-exam-g6       (เก็บไฟล์ข้อสอบ G6)
 │    ├── 📄 index.html
 │    └── 📁 images
 │
 └── 📁 folder-admission     (เก็บไฟล์สอบเข้า ม.1)
      ├── 📄 index.html
      └── 📁 images

3 สั่งผูก Target Alias ใน Terminal/Command Prompt

เปิด Terminal ที่ตำแหน่ง G:\owlvy-carefulness-contest> แล้วพิมพ์คำสั่งผูก Alias:

# 1. ผูกไซต์แข่งขันเดิม
firebase target:apply hosting target-contest owlvy-carefulness-contest

# 2. ผูกไซต์ข้อสอบ G6
firebase target:apply hosting target-g6 owlvytrio-g6-classroom-ai-exam-live

# 3. ผูกไซต์สอบเข้า ม.1
firebase target:apply hosting target-g7 admission-to-g7-live-test

4 เขียนไฟล์ตั้งค่า firebase.json (แบบ Array รองรับ Multi-Site)

เปิดไฟล์ firebase.json แล้วแก้ไขให้อยู่ในโครงสร้าง Array [ ... ] เพื่อรวมการตั้งค่าทั้งหมดไว้ด้วยกัน:

{
  "hosting": [
    {
      "target": "target-contest",
      "public": "folder-contest",
      "ignore": [
        "firebase.json",
        "**/.*",
        "**/node_modules/**"
      ]
    },
    {
      "target": "target-g6",
      "public": "folder-exam-g6",
      "ignore": [
        "firebase.json",
        "**/.*",
        "**/node_modules/**"
      ]
    },
    {
      "target": "target-g7",
      "public": "folder-admission",
      "ignore": [
        "firebase.json",
        "**/.*",
        "**/node_modules/**"
      ]
    }
  ]
}

5 การสั่ง Deploy ขึ้นเซิร์ฟเวอร์ (แยกอัปโหลดรายไซต์)

เมื่อต้องการอัปเดตไฟล์ขึ้นเว็บ **ให้ใช้คำสั่งเจาะจงเฉพาะ Target นั้นๆ** เพื่อป้องกันไม่ให้กระทบเว็บอื่น:

# เมื่อต้องการอัปเดตเว็บข้อสอบ G6 อย่างเดียว:
firebase deploy --only hosting:target-g6

# เมื่อต้องการอัปเดตเว็บสอบเข้า ม.1 อย่างเดียว:
firebase deploy --only hosting:target-g7

# เมื่อต้องการอัปเดตเว็บแข่งเดิมอย่างเดียว:
firebase deploy --only hosting:target-contest

⚠️ ข้อควรระวังระดับสำคัญมาก! (Crucial Precautions)

  • ห้ามเขียนทับแบบ Object เด็ดขาด: การแก้ไฟล์ firebase.json ต้องรักษาโครงสร้าง Array [ { ... }, { ... } ] ไว้เสมอ หากเผลอนำโค้ดไซต์เดียวไปวางทับ ไซต์อื่นๆ ในโปรเจกต์จะหลุดและทำงานไม่ได้
  • ระวังคำสั่ง firebase deploy ลอยๆ: หากไม่ใส่ --only hosting:target-xxxx ระบบจะทำการอัปโหลดไฟล์ทุกไซต์พร้อมกันทั้งหมด ซึ่งอาจนำไฟล์ทดสอบไปทับหน้าเว็บที่ใช้งานจริงได้
  • การอ้างอิงรูปภาพใน HTML: ให้ใช้ Relative Path เสมอ เช่น <img src="images/question1.png"> ห้ามใช้ Full Path จากเครื่องคอมพิวเตอร์ (C:/...)
  • ทุกโฟลเดอร์ต้องมีไฟล์ index.html: โฟลเดอร์ย่อยที่ระบุในช่อง "public" ต้องมีไฟล์ index.html เป็นหน้าแรกเสมอ
