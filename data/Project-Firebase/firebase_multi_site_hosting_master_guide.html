หัวใจสำคัญ: ระบบสะพานเชื่อม 2 ต่อ (2-Stage Binding Architecture)

คำสั่ง firebase target:apply คือตัวเชื่อมระหว่าง Site ID บน Cloud กับ Local Folder

ในระบบ Firebase Multi-Site คุณ **ไม่สามารถ** สั่งผูก Local Folder เข้ากับ Site ID บน Cloud ได้โดยตรง แต่มันจะทำงานผ่าน **สะพานเชื่อม 2 ต่อ** ดังนี้:

🔄 แผนผังแสดงสะพานเชื่อมระบบ (2-Stage Binding Architecture)
1. Local Public Folder

โฟลเดอร์งานในเครื่อง เช่น

folder-admission
กำหนดด้วย firebase.json ➔ "target": "target-g7" ➔ ช่อง "public"
2. Target Alias (ตัวกลาง)

ชื่อรหัสสะพานเชื่อม เช่น

owlvyhouse-entrance-g7-admission
⚡ เชื่อมต่อไปยัง Cloud ด้วย Terminal (บันทึกลงไฟล์ซ่อน .firebaserc) firebase target:apply hosting [Target-Alias] [Cloud-Site-ID]
3. Firebase Site ID (บน Cloud)

ชื่อ Web App ที่กดสร้างไว้ใน Firebase Console

owlvyhouse-entrance-g7-admission

กฎเหล็กป้องกันปัญหาที่มักพลาดประจำ!

  • ตำแหน่งในการรัน Terminal: ต้องรันคำสั่งอยู่ที่ Root Folder นอกสุดเสมอ (`G:\owlvy-carefulness-contest-main>`) ห้าม cd เข้าไปรันในโฟลเดอร์ย่อยเด็ดขาด!
  • เรื่องไฟล์ `index.html` ที่ Root: **ที่ Root นอกสุด ไม่ต้องมีไฟล์ `index.html`** และ Firebase จะไม่ข้ามมาดึงไฟล์ที่ Root หรือข้ามไปดึง Site อื่นอัตโนมัติ 100%
  • ลำดับขั้นตอน: ต้องกดสร้าง Site บน Console ➔ สั่ง `target:apply` ➔ เขียน `firebase.json` ➔ สั่ง `deploy`

1 กดสร้าง Site ID บน Firebase Console (จองที่ดินบน Cloud)

  1. เข้าเว็บไซต์ Firebase Console เลือกโปรเจกต์ owlvy-carefulness-contest
  2. ไปที่เมนู **Build ➔ Hosting**
  3. เลื่อนลงด้านล่างสุด หัวข้อ **Advanced (ขั้นสูง)** คลิกปุ่ม **Add another site**
  4. กดสร้าง Site ID เช่น owlvyhouse-entrance-g7-admission

2 สั่งผูก Target ใน Terminal (เปิด Terminal ที่ Root นอกสุดเท่านั้น)

เปิด Terminal ที่พาธ G:\owlvy-carefulness-contest-main> แล้วรันคำสั่งผูก Alias: 

firebase target:apply hosting target-contest owlvy-carefulness-contest
firebase target:apply hosting owlvytrio-g6-classroom-ai-exam-live owlvytrio-g6-classroom-ai-exam-live
firebase target:apply hosting owlvyhouse-entrance-g7-admission owlvyhouse-entrance-g7-admission

การเปิดใช้งาน Google Authentication (Google Sign-In)

ขั้นตอนการเปิด Sign-in Method บน Console และโครงสร้างโค้ดใช้งานจริง

🛠️ ขั้นตอนเปิดใช้งานบน Firebase Console (ทำครั้งเดียว):

  1. ไปที่ Firebase Console ➔ Build ➔ Authentication กด Get Started
  2. เลือกแท็บ Sign-in method ➔ คลิก Google
  3. สวิตช์เปิด Enable ➔ เลือก Project support email ➔ กด Save
HTML + Firebase Auth SDK v10 Implementation: 
<!-- Firebase Authentication Standard Implementation -->
<script type="module">
  import { initializeApp } from "https://www.gstatic.com/firebasejs/10.12.0/firebase-app.js";
  import { 
      getAuth, 
      signInWithPopup, 
      GoogleAuthProvider, 
      onAuthStateChanged, 
      signOut 
  } from "https://www.gstatic.com/firebasejs/10.12.0/firebase-auth.js";

  const firebaseConfig = {
      apiKey: "YOUR_API_KEY",
      authDomain: "owlvy-carefulness-contest.firebaseapp.com",
      projectId: "owlvy-carefulness-contest",
      storageBucket: "owlvy-carefulness-contest.appspot.com",
      messagingSenderId: "YOUR_SENDER_ID",
      appId: "YOUR_APP_ID"
  };

  const app = initializeApp(firebaseConfig);
  const auth = getAuth(app);
  const provider = new GoogleAuthProvider();

  // Auto check login status
  onAuthStateChanged(auth, (user) => {
      if (user) {
          console.log("เข้าสู่ระบบเรียบร้อย:", user.displayName, user.email);
          // ดึงโปรไฟล์ user.displayName, user.email, user.photoURL มาแสดง
      } else {
          console.log("ยังไม่ได้เข้าสู่ระบบ");
      }
  });

  // Login Function Trigger
  function loginWithGoogle() {
      signInWithPopup(auth, provider).catch(err => alert("Login Error: " + err.message));
  }
</script>

could not find site "xxx" for project "yyy" พิมพ์ชื่อ Site สเปลก์ผิด หรือยังไม่ได้กด Add Site บน Console เช็กชื่อบน Console ➔ กด Add site ➔ รัน target:apply ใหม่ให้ตรงกัน
Hosting site or target not detected in firebase.json ยังไม่ได้กด Save ไฟล์ JSON หรือพิมพ์ชื่อ Target ใน JSON ไม่ตรงกับ Terminal กด Save (Ctrl+S) และตรวจเช็กการสะกดชื่อ Target ให้ตรงกัน 100%
