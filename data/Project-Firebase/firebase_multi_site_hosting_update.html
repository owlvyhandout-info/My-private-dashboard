คู่มือระบบ Firebase Hosting (Multi-Site Target Binding Architecture)
ฉบับอธิบายเจาะลึกระบบสะพานเชื่อม (Target Binding Concept)

🔗 คู่มือตั้งค่า Firebase Multi-Site Hosting

เจาะลึกกลไกการทำงานของคำสั่ง firebase target:apply ตัวเชื่อมประสานหลักที่จับคู่ระหว่าง **Site ID บน Cloud** กับ **โฟลเดอร์งานในคอมพิวเตอร์**

Root Directory: G:\owlvy-carefulness-contest-main\ Main Project: owlvy-carefulness-contest
💡

ความเข้าใจผิดที่สำคัญ: Target Name ไม่ใช่แค่ "ชื่อย่อ" ไว้พิมพ์ง่าย!

มันคือ **"ตัวเชื่อมสะพาน 2 ต่อ"** ที่ขาดไม่ได้เด็ดขาดในการทำ Multi-Site

ในระบบ Firebase Multi-Site คุณ **ไม่สามารถ** สั่งผูก Local Folder เข้ากับ Site ID บน Cloud ได้โดยตรง แต่มันจะทำงานผ่าน **สะพานเชื่อม 2 ต่อ (2-Stage Binding)** ดังนี้:

🔄 แผนผังแสดงสะพานเชื่อมระบบ (2-Stage Binding Architecture)
1. Local Folder (ในคอม)

โฟลเดอร์งานจริง เช่น

folder-exam-g6
เชื่อมด้วย firebase.json ➔ "target": "target-g6" ➔ กำหนดช่อง "public"
2. Target Name (ตัวกลาง)

ชื่อรหัสเชื่อมต่อ เช่น

target-g6
⚡ เชื่อมต่อไปยัง Cloud ด้วยคำสั่ง Terminal (บันทึกลงไฟล์ .firebaserc) firebase target:apply hosting target-g6 owlvytrio-g6-classroom-ai-exam-live
3. Firebase Site ID (บน Cloud)

ชื่อ Web App ที่สร้างใน Firebase Console

owlvytrio-g6-classroom-ai-exam-live

สรุปสั้นๆ ให้จำง่าย:

  • คำสั่ง firebase target:apply คือคำสั่ง **สร้างสายเคเบิลเชื่อมต่อระหว่าง Target Name กับ Cloud Site ID**
  • ถ้าไม่รันคำสั่งนี้ ถึงแม้จะเขียนไฟล์ firebase.json ไว้ถูกต้อง ระบบก็จะไม่รู้ว่าโฟลเดอร์นั้นต้องส่งไปที่ Web App ตัวไหนบน Cloud!

📌 ตารางการผูกเชื่อมต่อ 3 โฟลเดอร์ย่อย ➔ 3 Web Apps

โฟลเดอร์ในเครื่อง (Local Public) Target Name (สะพานเชื่อม) Site ID บน Firebase Cloud Live Web App URL
folder-contest target-contest owlvy-carefulness-contest owlvy-carefulness-contest.web.app
folder-exam-g6 owlvytrio-g6-classroom-ai-exam-live owlvytrio-g6-classroom-ai-exam-live owlvytrio-g6-...web.app
folder-admission owlvyhouse-entrance-g7-admission owlvyhouse-entrance-g7-admission owlvyhouse-entrance-g7-...web.app

*หมายเหตุ: ในแถบ Target Name สองลำดับล่าง ตัวอย่างใช้ชื่อ Site ID เป็นชื่อ Target Name ตรงๆ เพื่อป้องกันความสับสนและจำง่ายที่สุด

1 สร้าง Site บน Firebase Console (ฝั่ง Cloud)

  1. เข้าเว็บไซต์ Firebase Console เลือกโปรเจกต์หลัก owlvy-carefulness-contest
  2. ไปที่เมนู **Build (สร้าง)** > **Hosting (โฮสติ้ง)**
  3. เลื่อนลงด้านล่างสุด หัวข้อ **Advanced (ขั้นสูง)** คลิกปุ่ม **Add another site**
  4. กดสร้าง Site ID ใหม่ตามต้องการ เช่น owlvytrio-g6-classroom-ai-exam-live

2 จัดโครงสร้างโฟลเดอร์ในคอมพิวเตอร์ (Local Drive)

ย้ายไฟล์ของทุกไซต์เข้าโฟลเดอร์ย่อยของใครของมัน **ที่ Root นอกสุดให้เหลือไว้เฉพาะไฟล์ตั้งค่าเท่านั้น (ไม่มี `index.html` อยู่ที่ Root)**: 

📁 G:\owlvy-carefulness-contest-main\  (โฟลเดอร์หลักนอกสุด เปลี่ยนชื่อโฟลเดอร์นี้ได้ตลอดเวลา)
 ├── 📄 .firebaserc                    (ไฟล์เก็บการจับคู่ Target Name ↔ Cloud Site ID)
 ├── 📄 firebase.json                  (ไฟล์ตั้งค่าหลัก - ชี้ Target Name ➔ Local Public Folder)
 │
 ├── 📁 folder-contest                 (เก็บไฟล์เว็บแข่งเดิม index.html, images)
 ├── 📁 folder-exam-g6                (เก็บไฟล์ข้อสอบ G6)
 └── 📁 folder-admission              (เก็บไฟล์สอบเข้า ม.1)

3 สั่งผูกสะพานเชื่อม Target ใน Terminal (ขั้นตอนสำคัญที่สุด!)

Mandatory Command

เปิด Terminal ที่ตำแหน่งโฟลเดอร์หลัก G:\owlvy-carefulness-contest-main> แล้วรันคำสั่งโครงสร้าง:
firebase target:apply hosting [Target-Name] [Site-ID-บน-Cloud]

ทางเลือก A: ใช้ชื่อ Site ID เป็น Target Name ซ้ำกันไปเลย (แนะนำที่สุด - ไม่สับสน)

พิมพ์ชื่อ Site ID ต่อท้าย 2 ครั้งไปเลย เพื่อไม่ต้องจำชื่อย่อเพิ่ม:

firebase target:apply hosting target-contest owlvy-carefulness-contest
firebase target:apply hosting owlvytrio-g6-classroom-ai-exam-live owlvytrio-g6-classroom-ai-exam-live
firebase target:apply hosting owlvyhouse-entrance-g7-admission owlvyhouse-entrance-g7-admission
ทางเลือก B: ตั้ง Alias ชื่อย่อใหม่ในเครื่อง

กำหนดชื่อย่อสั้นๆ ในเครื่องเพื่อความสั้นกระชับในการพิมพ์:

firebase target:apply hosting target-contest owlvy-carefulness-contest
firebase target:apply hosting target-g6 owlvytrio-g6-classroom-ai-exam-live
firebase target:apply hosting target-g7 owlvyhouse-entrance-g7-admission

4 เขียนไฟล์ตั้งค่า firebase.json (จับคู่ Target Name ➔ Local Public Folder)

เปิดไฟล์ firebase.json แล้วระบุค่า "target" ให้ตรงกับ Target Name ที่รันคำสั่งไว้ในสเต็ปที่ 3 และระบุ "public" ให้ตรงกับชื่อโฟลเดอร์ในเครื่อง: 

{
  "hosting": [
    {
      "target": "target-contest",
      "public": "folder-contest",
      "ignore": [
        "firebase.json",
        "**/.*",
        "**/node_modules/**"
      ]
    },
    {
      "target": "owlvytrio-g6-classroom-ai-exam-live",
      "public": "folder-exam-g6",
      "ignore": [
        "firebase.json",
        "**/.*",
        "**/node_modules/**"
      ]
    },
    {
      "target": "owlvyhouse-entrance-g7-admission",
      "public": "folder-admission",
      "ignore": [
        "firebase.json",
        "**/.*",
        "**/node_modules/**"
      ]
    }
  ]
}

5 การสั่ง Deploy ขึ้นเซิร์ฟเวอร์ (อ้างอิงชื่อ Target เสมอ)

เวลาสั่ง Deploy ให้พิมพ์ชื่อหลัง hosting: ให้ตรงกับค่า **`"target"`** ในไฟล์ `firebase.json`:

# กรณีใช้ Site ID เป็นชื่อ Target (ตามตัวอย่างในสเต็ป 4):

firebase deploy --only hosting:owlvytrio-g6-classroom-ai-exam-live

firebase deploy --only hosting:owlvyhouse-entrance-g7-admission

# กรณีตั้ง Alias ย่อ (เช่น target-g6, target-g7):

firebase deploy --only hosting:target-g6

firebase deploy --only hosting:target-g7

🔄 สรุปตารางรับมือ: เมื่อมีการเปลี่ยนแปลงตัวใดตัวหนึ่ง ต้องแก้ที่ไหนบ้าง?

หากในอนาคตมีการเปลี่ยนชื่อส่วนใดส่วนหนึ่ง ให้ทำตามแนวทางนี้เพื่อไม่ให้ระบบพังครับ:

สิ่งที่เปลี่ยนแปลง ต้องรัน Terminal ใหม่ไหม? ต้องแก้ไฟล์ firebase.json ไหม? คำอธิบายเพิ่มเติม
1. เปลี่ยนชื่อโฟลเดอร์หลักนอกสุดในคอม
(G:\owlvy-carefulness-contest-main)		 ❌ ไม่ต้องรัน ❌ ไม่ต้องแก้ ไม่มีผลกระทบใดๆ แค่ `cd` เข้าโฟลเดอร์ชื่อใหม่ใน Terminal เท่านั้น
2. เปลี่ยนชื่อโฟลเดอร์ย่อยในคอม
(folder-exam-g6 ➔ folder-g6-new)		 ❌ ไม่ต้องรัน ✔️ ต้องแก้ แก้เฉพาะช่อง "public": "folder-g6-new" ในไฟล์ firebase.json
3. เปลี่ยนชื่อ Target Name
(target-g6 ➔ target-g6-v2)		 ✔️ ต้องรันใหม่ ✔️ ต้องแก้ ต้องสั่ง target:apply ใหม่ และไปแก้ค่า "target" ใน JSON ให้ตรงกัน
4. สร้าง Site ID ใหม่บน Cloud
(สร้าง Web App ใหม่บน Firebase)		 ✔️ ต้องรันใหม่ ✔️ ต้องเพิ่มบล็อก ต้องสั่ง target:apply ชี้ไป Site ใหม่ และเพิ่มบล็อก JSON ชุดใหม่

⚠️ การแก้ปัญหายอดฮิต: "Hosting site or target xxx not detected in firebase.json"

หากเจอ Error นี้ ให้เช็กตามลำดับสติ 3 ขั้นตอนดังนี้ครับ:

  1. ลืมกด Save (`Ctrl + S`): ให้กดบันทึกไฟล์ firebase.json ก่อนสั่ง Deploy เสมอ
  2. ยังไม่ได้รันคำสั่งผูก Target: ต้องรัน firebase target:apply hosting [Target-Name] [Site-ID] ใน Terminal ก่อนเสมอ
  3. พิมพ์ชื่อ Target ไม่ตรงกัน: ชื่อหลัง hosting: ในคำสั่ง Deploy ต้องสะกดตรงกับค่า "target" ในไฟล์ firebase.json แบบ 100%
