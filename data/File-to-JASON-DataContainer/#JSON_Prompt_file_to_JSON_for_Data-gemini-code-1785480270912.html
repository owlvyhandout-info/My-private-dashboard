📘 สรุปการทำงานและความสัมพันธ์ของฟิลด์ในโครงสร้าง JSON ข้อสอบ

เอกสารนี้สรุปหลักการสำคัญในการจัดการฟิลด์ข้อมูล JSON สำหรับชุดข้อสอบ ทั้งในมุมมองของการสร้างข้อมูล (Data Creation / AI Prompt) และการนำไปแสดงผลบนหน้าเว็บ (Frontend Rendering) เพื่อให้แน่ใจว่าระบบทำงานได้อย่างถูกต้อง สมบูรณ์ และไม่เกิดข้อผิดพลาด

1. ตารางสรุปหน้าที่และความสัมพันธ์ของแต่ละฟิลด์

ชื่อฟิลด์ (Key) ประเภท (Type) สถานะ หน้าที่และการแสดงผล การใช้งานตามสถานะหน้าจอ (State)
id Integer จำเป็น รหัสประจำข้อสอบ (Unique ID) ใช้งานตลอดเวลา (ใช้เป็น Index)
topic String จำเป็น หมวดหมู่วิชา (เช่น "Bio", "Phys") ใช้คัดกรอง / จัดหมวดหมู่ข้อสอบ
title String (HTML) จำเป็น ข้อความโจทย์ + ตารางข้อมูล (HTML Table) แสดงผลทั้ง หน้าทำข้อสอบ และ หน้าเฉลย
image String จำเป็น Path ไฟล์รูปภาพประกอบโจทย์ (ถ้าไม่มีใส่ "") แสดงผลทั้ง หน้าทำข้อสอบ และ หน้าเฉลย
options Array [String] จำเป็น รายการตัวเลือกคำตอบ (รองรับ 2, 4, 5 ตัวเลือก) แสดงผลทั้ง หน้าทำข้อสอบ และ หน้าเฉลย
answer Integer จำเป็น ตัวเลขระบุตัวเลือกที่ถูกต้อง (1, 2, 3, ...) หน้าทำข้อสอบ: ซ่อนไว้
หน้าเฉลย: ใช้ตรวจคำตอบ
Hint String Optional คำใบ้สำหรับผู้สอบ (ถ้าไม่มีใส่ "") แสดงเมื่อผู้สอบกดขอคำใบ้ หรือซ่อนไว้
Explanation String (HTML) Optional คำอธิบายเฉลยอย่างละเอียด (ถ้าไม่มีใส่ "") หน้าทำข้อสอบ: ❌ ซ่อนไว้เด็ดขาด
หน้าเฉลย: ✅ แสดงผลใต้ตัวเลือก
info String (HTML) HTML Link ลิงก์แท็ก <a> อ่านเพิ่ม (ถ้าไม่มีใส่ "") หน้าทำข้อสอบ: ❌ ซ่อนไว้
หน้าเฉลย: ✅ แสดงผลล่างสุด

2. วงจรชีวิตและการแสดงผลข้อมูล (Data Workflow)

การเก็บฟิลด์ทั้งหมดไว้ใน Object เดียวกันช่วยให้บริหารจัดการข้อมูลได้ง่าย แต่ฝั่ง Frontend ต้องควบคุมการสั่ง Render ตามสถานะหน้าจอ (State Control) เพื่อไม่ให้เกิดการแอบดูเฉลย:

1. 📄 JSON Data

เก็บข้อมูลครบทุกฟิลด์ใน 1 Object (โจทย์, ตัวเลือก, เฉลย, ลิงก์)

➔

2. 📝 Exam Mode

Fetch เฉพาะ:
title, image, options
(ซ่อน answer, Explanation, info)

➔

3. 💡 Solution Mode

Fetch ทั้งหมด:
เปรียบเทียบ answer และสั่งเปิดการแสดงผล Explanation + info

3. กฎสำคัญในการจัดการฟิลด์โครงสร้างพิเศษ

ก. การจัดการตารางในโจทย์ (Table Handling)

หากในโจทย์มีข้อมูลที่เป็นตาราง ห้ามใช้การเว้นบรรทัดด้วย <br> เด็ดขาด เพราะจะทำให้โครงสร้างตารางพัง ให้แปลงตารางเป็น HTML Table เสมอ:

รูปแบบที่ถูกต้อง:
<table border='1'><tr><th>หัวข้อ</th></tr><tr><td>ข้อมูล</td></tr><</table>

กรณีพิเศษ: หากตัวเลือก 1-4 ถูกจัดอยู่ในรูปตาราง ให้ดึงตารางนั้นมาวางไว้ใน title แล้วสรุปตัวเลือกใน options ให้กระชับ เช่น ["(1) 1", "(2) 2", "(3) 3", "(4) 4"]

ข. การจัดการฟิลด์ HTML Link (info)

ฟิลด์ info ใช้เก็บลิงก์อ้างอิงภายนอก ต้องเขียนแท็ก HTML ให้สมบูรณ์ และระบุ target='_blank' เพื่อให้กดแล้วเปิดแท็บใหม่ ไม่กระทบกับหน้าทำข้อสอบเดิม

"info": "<br><a href='https://...' target='_blank'>ลิงก์อ้างอิง 1</a>"

4. การนำไปปฏิบัติฝั่ง Frontend (Coding Standards)

ข้อควรระวังเรื่อง HTML Rendering: ฟิลด์ที่มีโครงสร้าง HTML เช่น title, Explanation และ info หากดึงไปแสดงผลเป็น Text ธรรมดา หน้าจอจะโชว์โค้ดดิบๆ ไม่กลายเป็นตารางหรือลิงก์ให้กด!

ก. การตั้งค่าการ Render ของแต่ละ Framework

  • Vanilla JavaScript: ต้องใช้ .innerHTML (ห้ามใช้ .innerText) 
    document.getElementById("info-container").innerHTML = item.info;
  • React: ต้องใช้ dangerouslySetInnerHTML 
    <div dangerouslySetInnerHTML={{ __html: item.info }} />
  • Vue.js: ต้องใช้ดิเรกทีฟ v-html 
    <div v-html="item.info"></div>

ข. การจัดการฟิลด์ที่ไม่แน่นอน (Optional Fields Handling)

เนื่องจากฟิลด์อย่าง Explanation, Hint หรือ info บางข้ออาจมีข้อมูล แต่บางข้อเป็นค่าว่าง "" เพื่อป้องกันไม่ให้หน้าจอขึ้นพื้นที่ว่างเปล่า (Empty Space) หรือเกิด Error ควรสร้าง Helper Function กลาง มาจัดการดังนี้:

// ฟังก์ชันกลางสำหรับ Render ฟิลด์ทางเลือก
function renderOptionalContent(elementId, content) {
    const el = document.getElementById(elementId);
    if (!el) return; // ป้องกัน Error ถ้าหา Element ไม่เจอ

    // เช็กว่ามีข้อมูลจริง และไม่ใช่แค่เว้นวรรคว่าง
    if (content && content.trim() !== "") {
        el.innerHTML = content;
        el.style.display = "block"; // แสดงกล่องเมื่อมีข้อมูล
    } else {
        el.innerHTML = "";
        el.style.display = "none";  // ซ่อนกล่องเมื่อไม่มีข้อมูล
    }
}

// 🚀 การนำไปใช้งานจริง (บรรทัดเดียวต่อ 1 ฟิลด์)
renderOptionalContent("explain-container", item.Explanation);
renderOptionalContent("info-container", item.info);
renderOptionalContent("hint-container", item.Hint);

5. โครงสร้าง HTML Element บนหน้าเว็บที่ต้องเตรียมไว้ (DOM Structure)

ฝั่ง HTML หน้าเว็บต้องทำการสร้าง "กล่องรับข้อมูล" (Element Container) มารองรับไว้ล่วงหน้า ดังตัวอย่างนี้:

<!-- โครงสร้างหน้าเฉลยข้อสอบ -->
<div class="question-card">
  <div id="title-container"></div>      <!-- จุดแสดงโจทย์ + ตาราง -->
  <div id="image-container"></div>      <!-- จุดแสดงรูปภาพ -->
  <div id="options-container"></div>    <!-- จุดแสดงตัวเลือก -->
  
  <!-- ฟิลด์ส่วนเสริมที่จะถูกเปิดใช้งานในหน้าเฉลย -->
  <div id="explain-container" style="display:none;"></div>  <!-- กล่องคำอธิบายเฉลย -->
  <div id="info-container" style="display:none;"></div>     <!-- กล่องลิงก์อ้างอิง -->
</div>
