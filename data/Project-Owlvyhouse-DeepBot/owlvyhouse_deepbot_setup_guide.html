🔄 Flow การทำงาน

สร้าง Firebase Project

Firebase Console
ทำตามลำดับ ขั้นตอนสร้าง Project
  1. ไปที่ console.firebase.google.com → Login ด้วย Google Account
  2. กด "Add project" (หรือ "Create a project")
  3. ตั้งชื่อ project เช่น owlvyhousedeep-bot → กด Continue
  4. เลือกว่าจะเปิด Google Analytics หรือไม่ (ไม่บังคับ) → กด "Create project"
  5. รอสักครู่จนหน้า Dashboard ขึ้น → Project พร้อมใช้งาน
ได้ firebaseConfig เพิ่ม Web App เพื่อรับ Config
  1. ในหน้า Project Overview → กดไอคอน "</>" (Web)
  2. ตั้งชื่อ App เช่น owlvy-web → กด "Register app"
  3. Firebase จะแสดง firebaseConfig — Copy เก็บไว้ทั้งหมด
  4. กด "Continue to console"
firebaseConfig (ตัวอย่าง) 
const firebaseConfig = {
  apiKey:            "AIzaSyXXXXXXXXXXXXXXXXXX",
  authDomain:        "owlvyhousedeep-bot.firebaseapp.com",
  projectId:         "owlvyhousedeep-bot",
  storageBucket:     "owlvyhousedeep-bot.firebasestorage.app",
  messagingSenderId: "712345678901",
  appId:             "1:712345678901:web:0abc1234def56789"
};
⚠️
ห้าม commit ไฟล์ที่มี apiKey ขึ้น GitHub แบบ public — ถ้า deploy บน GitHub Pages ค่าเหล่านี้จะเปิดเผยสู่สาธารณะ แต่สำหรับโปรเจกต์นี้ถือว่ารับได้เพราะ Security Rules จะป้องกันการอ่านข้อมูลโดยไม่ผ่าน Login

เปิด Google Authentication

Firebase → Authentication
ทำตามลำดับ ตั้งค่า Sign-in Method
  1. Sidebar ซ้าย → กด "Authentication"
  2. กดแท็บ "Sign-in method"
  3. กดที่ "Google" ในรายการ Sign-in providers
  4. Toggle "Enable" เปิดใช้งาน
  5. ตั้ง Project support email เป็นอีเมลของคุณ
  6. กด "Save"
สำคัญ เพิ่ม Authorized Domain
  1. ยังอยู่ในหน้า Sign-in method → เลื่อนลงหา "Authorized domains"
  2. ถ้ารัน local: localhost มีอยู่แล้วอัตโนมัติ
    ถ้า deploy บน GitHub Pages: กด "Add domain" → ใส่ domain เช่น owlvyhandout-info.github.io
🚫
ถ้าไม่เพิ่ม domain จะ Login ไม่ได้ — Firebase จะ block popup และแสดง error "auth/unauthorized-domain"

ตั้งค่า Firestore Database

Firebase → Firestore Database
ทำตามลำดับ สร้าง Database
  1. Sidebar ซ้าย → กด "Firestore Database"
  2. กด "Create database"
  3. เลือก "Production mode" (ล็อกทุกอย่างก่อน)
  4. เลือก Location: asia-southeast1 (สิงคโปร์ — ใกล้ไทย)
  5. กด "Done" → รอ Firestore พร้อมใช้งาน
สร้าง Document เก็บ OpenRouter API Key

ระบบดึง Key จาก path นี้ตอน Login:

config / openrouter → field: apiKey = "sk-or-v1-XXXXXX"
  1. ในหน้า Firestore → กด "+ Start collection"
  2. Collection ID: config → กด Next
  3. Document ID: openrouter (พิมพ์เอง)
  4. กด "+ Add field" → Field name: apiKey → Type: string
  5. Value: ใส่ OpenRouter API Key ของคุณ (เริ่มด้วย sk-or-v1-)
  6. กด "Save"
ความปลอดภัย ตั้ง Security Rules

Sidebar → Firestore → แท็บ "Rules" → แทนที่ด้วย:

firestore.rules 
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // collection "config" — อ่านได้เฉพาะ login แล้ว, เขียนไม่ได้จาก client
    match /config/{docId} {
      allow read:  if request.auth != null;
      allow write: if false;
    }

    // ทุกอย่างอื่น — ปิดทั้งหมด
    match /{document=**} {
      allow read, write: if false;
    }
  }
}
  1. วาง Rules ด้านบนแทนที่ข้อความเดิม
  2. กด "Publish" (สำคัญ — ถ้าไม่ Publish Rules ไม่มีผล)

ได้ OpenRouter API Key

OpenRouter.ai
ทำตามลำดับ สมัครและได้ Key
  1. ไปที่ openrouter.ai → กด "Sign In"
  2. Login ด้วย Google / Email
  3. เมนูบน → "Keys" → กด "Create Key"
  4. ตั้งชื่อ Key เช่น owlvy-bot → กด "Create"
  5. Copy Key ที่ขึ้นต้นด้วย sk-or-v1-XXXXXX → เก็บไว้ (เห็นครั้งเดียว!)
  6. เติมเครดิต: เมนู "Credits" → เติมขั้นต่ำ $5 ด้วยบัตรเครดิต
✅
Key นี้นำไปใส่ใน Firestore ตามขั้นตอน 4 → ระบบจะดึงมาใช้อัตโนมัติตอน Login

ตรวจสอบ — Key ถูกดึงอัตโนมัติ

โค้ดใน HTML
โค้ดอ้างอิง การดึง Key จาก Firestore (มีในไฟล์แล้ว)

ส่วนนี้ทำงานอัตโนมัติหลัง Login — ไม่ต้องแก้ไข แค่ให้เข้าใจ:

firebase script (มีอยู่แล้วในไฟล์) 
onAuthStateChanged(auth, async (user) => {
  if (user) {
    // ดึง API Key จาก Firestore path: config/openrouter
    const snap = await getDoc(doc(db, 'config', 'openrouter'));
    if (snap.exists()) {
      window.OPENROUTER_API_KEY = snap.data().apiKey;
    } else {
      showError('ไม่พบ API Key ใน Firestore');
    }
  }
});
ℹ️
ถ้า Document หรือ Field ชื่อผิด (เช่น Config ตัวใหญ่ หรือ api_key) จะ error "ไม่พบ API Key" — ต้องตรงกันทุกตัวอักษร

ใส่ Firebase Config ใน HTML

แก้ไขไฟล์ HTML
แก้ไขไฟล์ เปิดไฟล์ HTML แล้วหา Firebase script
  1. เปิดไฟล์ owlvyhouse_deep_bot.html ด้วย Text Editor (VS Code แนะนำ)
  2. กด Ctrl+F ค้นหา AIxxxxxxxxxxxx หรือ firebaseConfig
  3. แทนที่ค่า placeholder ทั้งหมดด้วยค่าจริงที่ได้จาก Firebase Console
แก้ตรงนี้ในไฟล์ HTML (บรรทัดประมาณ 267–273) 
// 🔧 แทนที่ด้วยค่าจาก Firebase Console → Project Settings → Your apps
const firebaseConfig = {
  apiKey:            "AIzaSyแทนที่ด้วยค่าจริง",
  authDomain:        "your-project-id.firebaseapp.com",
  projectId:         "your-project-id",
  storageBucket:     "your-project-id.firebasestorage.app",
  messagingSenderId: "ตัวเลข 12 หลัก",
  appId:             "1:messagingSenderId:web:ตัวเลขและตัวอักษร"
};
ทดสอบ local รัน HTML บนเครื่อง
  1. ถ้าใช้ VS Code → ติดตั้ง Extension "Live Server"
  2. คลิกขวาที่ไฟล์ → "Open with Live Server"
  3. Browser จะเปิด http://127.0.0.1:5500/... → ทดสอบ Login ได้เลย
⚠️
ห้ามเปิดไฟล์ด้วย file:// ตรง ๆ (ดับเบิ้ลคลิก) — Firebase Auth ไม่รองรับ protocol นี้ ต้องเปิดผ่าน http://localhost

AI Fallback System และ Free Models

โค้ด generateQuestions()
Fallback Logic ระบบลองไป AI ถัดไปอัตโนมัติ

เมื่อกด "สร้างคำถาม" ระบบจะลอง AI ตาม MODELS array ตามลำดับ — ถ้าตัวไหน error จะข้ามไปตัวถัดไปทันที:

generateQuestions() — Fallback loop 
const MODELS = [
  "google/gemini-flash-1.5",        ← ลองตัวนี้ก่อน (เร็ว + ถูก)
  "deepseek/deepseek-chat",          ← Fallback 2
  "anthropic/claude-3-haiku",       ← Fallback 3
  "meta-llama/llama-3.3-70b-versatile", ← Fallback 4
  "anthropic/claude-3.5-sonnet"    ← Fallback สุดท้าย (แพงสุด)
];

for (let i = 0; i < MODELS.length; i++) {
  try {
    res = await callOpenRouter(prompt, MODELS[i]);
    usedModel = MODELS[i];
    break;              ← สำเร็จ → หยุด loop
  } catch (e) {
    if (i === MODELS.length - 1) {
      showError('ไม่สามารถเชื่อมต่อ AI ได้');
    }
    // ถ้าไม่ใช่ตัวสุดท้าย → วน loop ต่อไปตัวถัดไป
  }
}
เครดิตหมด เพิ่ม Free Models รับมือเครดิต OpenRouter หมด

OpenRouter มี model บางตัวที่ใช้ฟรีได้ (ต่อท้าย :free) เพิ่มเข้าไปใน MODELS เพื่อให้ fallback ได้แม้เครดิตหมด:

แก้ไข MODELS array ในไฟล์ HTML (ประมาณบรรทัด 293) 
const MODELS = [
  // === เสียเงิน (ลองก่อน) ===
  "google/gemini-flash-1.5",
  "deepseek/deepseek-chat",
  "anthropic/claude-3-haiku",
  "meta-llama/llama-3.3-70b-versatile",
  "anthropic/claude-3.5-sonnet",
  // === ฟรี — fallback เมื่อเครดิตหมด ===
  "google/gemini-2.0-flash-exp:free",
  "deepseek/deepseek-chat:free",
  "meta-llama/llama-3.3-70b-instruct:free",
  "mistralai/mistral-7b-instruct:free"
];

ทดสอบระบบ — Checklist

ก่อน Deploy จริง
✅ Checklist ตรวจสอบทุกจุด
  • 🔥 Firebase Project สร้างแล้ว และ ได้ firebaseConfig
  • 🔐 Google Authentication เปิดใช้งานแล้ว + เพิ่ม Authorized Domain แล้ว
  • 🗄️ Firestore สร้างแล้ว + มี Document config/openrouter พร้อม field apiKey
  • 🔒 Security Rules ตั้งแล้วและกด Publish แล้ว
  • ✏️ ใส่ firebaseConfig จริงลงในไฟล์ HTML แล้ว
  • 🤖 OpenRouter API Key ใส่ใน Firestore แล้ว
  • 🔄 เพิ่ม Free Models ใน MODELS array แล้ว (ถ้าต้องการ)
🐛 ปัญหาที่พบบ่อยและวิธีแก้
Error / อาการ สาเหตุ วิธีแก้
auth/unauthorized-domain Domain ไม่อยู่ใน Authorized list Firebase Auth → Sign-in method → เพิ่ม domain
ไม่พบ API Key ใน Firestore ชื่อ Collection/Document/Field ผิด ตรวจสอบว่าเป็น config/openrouter/apiKey ตรงทุกตัวอักษร
Permission denied Security Rules ไม่ได้ Publish Firestore → Rules → กด Publish
ไม่สามารถเชื่อมต่อ AI OpenRouter Key หมด / ผิด เติมเครดิต หรือเพิ่ม free models ใน MODELS
Popup ถูก block Browser block popup อนุญาต popup สำหรับ domain นี้ใน Browser
Login ด้วย file:// ไม่ได้ Firebase ไม่รองรับ file protocol ใช้ Live Server หรือ deploy บน hosting
